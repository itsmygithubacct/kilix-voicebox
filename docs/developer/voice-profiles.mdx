## Overview

Voice profiles are the foundation of Voicebox's voice cloning capability. Each
profile stores exactly one consented source recording plus its metadata. The
source remains private product data unless an export explicitly includes it.

## Architecture

The voice profile system consists of three main components:

**Database Layer:** SQLite tables store profile metadata and sample references.

**File Storage:** The one source recording is stored privately under its profile.

**Profile Module:** The `profiles.py` module provides the business logic for CRUD operations.

## Data Model

### VoiceProfile Table

```python
class VoiceProfile(Base):
    __tablename__ = "profiles"
    
    id = Column(String, primary_key=True)
    name = Column(String, unique=True, nullable=False)
    description = Column(Text)
    language = Column(String, default="en")
    created_at = Column(DateTime)
    updated_at = Column(DateTime)
```

### ProfileSample Table

```python
class ProfileSample(Base):
    __tablename__ = "profile_samples"
    
    id = Column(String, primary_key=True)
    profile_id = Column(String, ForeignKey("profiles.id"))
    audio_path = Column(String, nullable=False)
    reference_text = Column(Text, nullable=False)
```

## File Structure

Profiles are stored in the data directory:

```
data/
└── profiles/
    └── {profile_id}/
        └── {sample_id}.wav
```

## Core Functions

### Creating a Profile

```python
async def create_profile(data: VoiceProfileCreate, db: Session) -> VoiceProfileResponse:
    # 1. Create database record
    db_profile = DBVoiceProfile(
        id=str(uuid.uuid4()),
        name=data.name,
        description=data.description,
        language=data.language,
    )
    db.add(db_profile)
    db.commit()
    
    # 2. Create profile directory
    profile_dir = profiles_dir / db_profile.id
    profile_dir.mkdir(parents=True, exist_ok=True)
    
    return VoiceProfileResponse.model_validate(db_profile)
```

### Adding Samples

The public API accepts a bounded upload, stages it in a private product-owned
file, and always removes that staging file. The profile layer refuses a second
source before decoding and chooses the permanent storage path itself; callers
never supply a destination path:

```python
async def add_profile_sample_upload(
    profile_id: str,
    file: UploadFile,
    reference_text: str,
    db: Session,
) -> ProfileSampleResponse:
    content = await _read_bounded_upload(file, MAX_SAMPLE_BYTES)
    staged = _stage_private_upload(content, ".wav")
    try:
        # profiles.add_profile_sample enforces the exact 1/1 population,
        # validates the recording, and commits to an owned private path.
        return await profiles.add_profile_sample(
            profile_id, str(staged), reference_text, db
        )
    finally:
        staged.unlink(missing_ok=True)
```

### Voice Prompt Creation

Voicebox resolves the one owned source descriptor, then delegates prompt
construction and synthesis to the provider orchestrator. The orchestrator
requires the request's explicit consent assertion and records consent and
generation provenance; Voicebox never calls a model directly:

```python
async def generate_speech(
    request: GenerationRequest,
    db: Session,
) -> dict:
    source = await profiles.create_voice_prompt_for_profile(
        request.profile_id, db
    )
    # This call returns only after consent and provenance validation and a
    # private, digest-bound generation commit.
    return await asyncio.to_thread(
        _voice_orchestrator().synthesize_clone,
        profile_id=request.profile_id,
        sample_path=Path(source["audio_path"]),
        text=request.text,
        language=request.language,
        consent_asserted=request.consent_asserted,
    )
```

The API then writes the relational history record. If that write fails, it
moves the already-created generation into private recoverable trash rather
than leaving an orphaned output.

## Audio Validation

Reference audio is validated before being accepted:

- **Duration:** 3-30 seconds recommended
- **Format:** WAV, MP3, FLAC, OGG supported
- **Sample Rate:** Resampled to 24kHz
- **Channels:** Converted to mono if stereo

## Export/Import

Profile export omits source audio by default:

```
profile_export.zip
├── manifest.json    # includes samples_included: false
└── samples.json     # empty
```

`GET /profiles/{id}/export?include_samples=true` is an explicit opt-in that
adds the one source WAV and its reference text. That archive contains biometric
source audio; export it only with the speaker's consent and the right to share
it.

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/profiles` | List all profiles |
| POST | `/profiles` | Create a profile |
| GET | `/profiles/{id}` | Get profile by ID |
| PUT | `/profiles/{id}` | Update profile |
| DELETE | `/profiles/{id}` | Delete profile |
| GET | `/profiles/{id}/samples` | Get profile samples |

| POST | `/profiles/import` | Import from ZIP |

## Best Practices

### Sample Quality

- Use clean audio with minimal background noise
- Ensure the reference text exactly matches what is spoken
- Exactly 1 consented source sample is supported; replace it to change the voice

### Language Matching

- Set the profile language to match the reference audio
- Supported languages: en, zh, ja, ko, de, fr, ru, pt, es, it

### Naming Conventions

- Use descriptive names that identify the voice
- Avoid special characters that may cause filesystem issues
